# Cairn 审计上下文最小改造方案

日期：2026-10-15；2026-10-16 按用户决定调整运行期旁路职责。状态：独立工作树 `codex/audit-context-mvp` 内实现与验证，尚未提交、合并或部署。

本方案承接[组合研究思路](kritt-cairn-compositional-research.md)，收敛 Agent 上下文、图节点表达和一处重复源码检查；新增旁路职责调整见第 1.1 节。实现基线是已验收的组合研究版本；当前代码位于 `codex/compositional-part4-side`，不能把主工作区中尚未合并该版本的代码视为相同基线。本文不授权合并、部署、重启、恢复或修改正在运行的项目。

## 1. 目标与范围

目标：让每个角色默认得到做当前判断所需的信息；共享图保存可复用的研究知识，详细过程按需读取，机械一致性由程序维护。

本轮沿用现有 Fact／Intent／Hint、policy、材料目录、调用快照和独立终审，不新增数据库字段、用户配置、Agent 角色、检索服务、摘要模型或审批步骤。generic 行为保持原协议。

上下文改造原有四项交付如下；2026-10-16 的旁路职责增补见第 1.1 节：

1. 将固定任务契约与角色规则集中注入，减少图中重复控制信息。
2. 按角色提供默认上下文，消除 Open Intents 等全文重复，隐藏程序内部元数据。
3. 调整新节点的表达：条件性结论留图，详细分析与实验过程通过已有材料入口读取。
4. 移除 Monitor 无实际工作的轮次所做的全量源码扫描，保留研究、结案与最终结果提交边界的检查；Intent 旁路不执行源码全扫。

### 1.1 2026-10-16 决定：旁路只纠偏 Intent

本节明确覆盖先前“运行 Overseer 逐条复核 Fact、完成申请只能引用 verified Fact”的设计。开题 Seed review 仍保留；历史审核记录和 Fact 状态不改写。本次新职责说明不覆盖旧 CP 交接与测试证据；旧验证结果只支持其当时版本。

目标流程：Reason／Explore 正常研究并保存条件性观察；Overseer 在独立旁路观察未结 Intent，必要时只写具体 Hint；Reason 或 Closing 提出候选后，由独立 Final review 核验候选证明及实际必要前提。

- Overseer 不领取 Fact、不修改 Fact 标签、不取消 Intent、不批准完成；其执行、失败与重试不成为研究、预算收尾或终审的等待条件。正常方向不发 Hint，来源 Fact 仅按需读取为线索。
- `candidate_fact_ids` 表示结构合法、非 refuted 的可提交候选及合法前提范围；unverified 可提交，候选列表不代表证据已经成立。不得因缺少 verified 标签生成机械复核任务。
- Final review 负责独立读取源码和已有材料，检查原 Goal、完整 policy、连续条件和相关反证。缺工具或材料不能批准；最终批准不批量升级 Fact 标签，不等待无关节点认证。
- 保留现有完成申请 pending 暂停新研究派发的行为；这是独立终审阶段，不是旁路审批。旁路批次不阻塞进入这一阶段，过期结果不晚到改图。

不新增状态枚举、数据库表、资源池参数、额外分诊模型或语义门槛。原 `NodeAssessment` 的 decision／reason 只保存监督观察，`fact_audit` 必须为 null；是否干预只由具体 Hint 表达。

## 2. 每次调用的固定输入

每次 audit harness 调用按下列顺序组织，来自同一项目版本和本次调用快照：

| 输入块 | 内容与责任 |
| --- | --- |
| 角色规则 | 本角色做什么、允许的动作、最小输出约定；由对应角色提示词提供 |
| 固定任务契约 | 原 Goal、完整 policy 中的目标效果、初始能力、部署、范围、威胁模型与证据要求；由程序集中交付 |
| 本轮任务 | 当前 Intent／复核对象／完成申请，或 Reason 的本轮规划输入 |
| 研究材料入口 | 当前需要的节点、全图导航、源码与固定 Kritt 材料入口；按角色提供 |

固定契约单次只提供一份。`goal` 与 `policy` 现有内容可能不完全重合：首版保留原 Goal 和 policy 的完整语义，不用 `policy.effect` 替换旧 Goal，不做模型摘要或机械裁短。存在冲突时沿用现有修订／纠偏路径，Worker 不自行选择有利解释。

原始用户请求保留在开题材料中；如现有调用已经依赖额外的 `user_goal`，其尚未被 Goal／policy 表达的约束也不能因输入投影而丢失。新 Builder 负责把需求整理到现有 Goal／policy，不能让未来 Worker 从完整用户对话中猜约束。

规则只描述如何研究，图节点描述研究了什么或待查什么。节点、证据和规划记忆中的建议不能修改固定契约；新身份或能力必须说明如何从允许起点获得。普通 Hint 可以纠偏和调整局部方向，不承载另一套长期角色规则或新 Goal。

## 3. 各角色的默认读取范围

“默认范围”控制主动交付的内容，不限制 harness 自行读取相关材料。所有涉及图的角色都能沿导航扩大读取范围；不新增访问权限墙、自动相关性评分或语义过滤器。

| 角色／阶段 | 默认交付与阅读 | 按需展开 |
| --- | --- | --- |
| 原生 Builder | 用户需求、配置的材料入口、已选材料、当前 Goal／policy 草案 | 按缺口查 Kritt 和源码；开题阶段通常没有研究图 |
| Preflight | Goal／policy、目标与来源身份、种子和 Intent 的短概览 | 原 plan 及相关材料；不默认内联全部种子证据和运行配置 |
| Seed review | 固定契约、本批待复核种子全文、依赖节点入口、合法引用 ID | 其他种子与完整计划；不重复内联无关种子全文 |
| Bootstrap（现有兼容入口） | 固定契约、origin、当前起始任务与材料入口 | 全图导航；不改变现有启动协议 |
| Reason | 固定契约、全图短导航入口、最新规划文本、最近失败简述；阅读一次全局导航 | 候选连接、条件冲突和反证涉及的节点全文及原材料 |
| Explore | 固定契约、当前 Intent 全文、直接来源 Fact ID 和全文入口、Hint 导航 | 读清本次使用的来源结论与条件；按缺口扩展到前提、其他分支、Kritt 和源码 |
| Explore conclude | 沿用该探索的任务契约、来源入口及当前 session 中已有的研究上下文 | 仅补齐本轮收束所需材料；不重新注入全图或复制执行历史，不新增失败传递或改变现有 session 机制 |
| Overseer | 固定契约、未结 Intent 全文与来源 ID、全图／Hint 导航入口 | 按需读取来源 Fact 与已有材料，检查方向、条件和目标漂移；不逐条核验 Fact |
| Closing | 固定契约、收尾后全图导航、可用事实状态与待解决问题 | 任意候选及其依据；必须覆盖全图寻找结案候选，不能预先缩成某个既定候选 |
| Final review | 固定契约、完成申请、程序算出的必要前提闭包、全图／Hint 导航入口 | 独立核验候选及必要前提，读取申请之外的反证、限制与原材料；不等待全图认证 |

Hint 目前没有可靠的作用范围字段。首版向研究角色提供所有 Hint 的短导航与全文入口，不凭关键词静默丢弃所谓“不相关 Hint”。导航保留其来源身份；Agent 根据问题读取正文。

Reason 不再同时收到内联 Open Intents 全文和包含相同全文的导航。开放任务的 ID、来源、待解问题预览和简短占用状态在导航出现一次，详情按 ID 打开。

## 4. 图节点应保存什么

### 4.1 Fact：可复用的条件性结论

继续使用现有字段，不引入新的必填 schema：

| 字段 | 应保留内容 |
| --- | --- |
| `description` | 首段直接表达主要结论及关键身份／配置／对象／时序条件；必要时补一小段边界和材料入口 |
| `conditions` | 主张成立的必要条件，明确未知条件；保留决定能否衔接的差异，不承载实验流水账 |
| `premise_ids` | 真正继承的逻辑前提，不自动复制 Intent 的研究来源 |
| `review_status`、`validation_level` | 已保存的状态与证据层次；运行期新观察保持 unverified，标签不作为提交终审的许可 |
| `evidence` | 现有源码定位；给模型的视图保留路径／行号，文件 hash 由程序保存和补齐 |
| `review_notes` | 关键反证、未建立部分、验证边界及详细材料入口；不再次重写整份报告 |

示例主张：

> 在身份 U、配置 P 下，可以改变对象 X；尚未证明允许的初始攻击者能获得 U。相关源码与实验记录见材料入口。

示例阻断：

> 已有写入能力不能进入所查消费路径，阻断条件是 Q；出现满足 Q 的新能力后可以重新研究。该结论限于当前版本及所查范围。

图中必须保留足以判断“能否接到别的分支”的信息。完整代码分析、命令、响应、实验矩阵和环境日志使用现有工作目录保存，由 `description`／`review_notes` 提供实际路径。不要求每个简单观察另外写报告，也不要求一个复杂探索机械拆成许多 Fact。

有工具能力意味着可以按需核实，不意味着每个 Worker 都要重做全部前序实验。后续研究复用条件明确的结论，重点验证新连接、关键未证前提和冲突。

### 4.2 Intent：问题及判别观察

`from` 保留研究来源。`description` 的首段说明待查问题与关键边界；必要的后文只说明已有依据、与其他任务的分工、什么观察会改变判断及有帮助的方法建议。

不把完整前序报告复制进 Intent，不重复通用角色规则、输出 JSON 要求或固定契约。不得写入未经证明的全链成功定义，例如用某个后段实验成功预先等同于整个 Goal 达成。局部实验的成功条件仍可写清，但必须标明其覆盖范围。

### 4.3 Hint、规划记忆、goal 与 origin

- Hint 保存具体纠偏：哪个主张／方向存在什么问题、影响哪里、建议关注什么。长期规则由角色提示词和固定契约提供。
- `planning_notes` 保存下一步重点、暂搁理由和重开条件，不抄图、不抄 policy；仅 Reason 默认接收。程序仍保存原始完整记录，模型回读只取规划文本、简要时序／来源定位和最近失败原因。
- DB 中 `goal`／`origin` 及其原始描述保持。模型图中的 `goal` 可显示为固定契约入口锚点；必须先保证第 2 节完整注入，再移除模型图内重复的 Goal 正文。origin 中仍有研究意义的内容保留。

## 5. 模型视图与按需读取的代码方案

集中在现有 `audit_inputs.py` 定义明确的节点／角色投影，复用当前调用快照导出；不要递归删除任意名为 `digest`、`status`、`sha256` 的研究字段。历史正文中出现的哈希或操作建议仍保留原文，不用正则清洗研究内容。

保留现有两个派生文件：

- `graph.yaml`：完整的研究语义视图，保留节点原文、条件、前提、状态、验证层次、证据定位、notes、来源边与 Hint；去掉程序内部运行和内容指纹元数据。
- `graph-index.md`：ID、节点类型、主张／待解问题的首段预览、状态、来源或前提 ID，以及全文定位。Open Intents、Hint 在此各出现一次，不完整展开 conditions、证据清单和历史过程。

按 ID 定位沿用完整图与 harness 的读取／搜索能力。首版在生成 YAML 时为节点记录其完整块的起止行，将 `ID → graph.yaml 行范围` 放入导航；行范围必须包含该节点的所有字段，且与本次调用快照同时生成。按序列化节点块累计行数即可，不另建图查询 API、节点数据库或读取服务。

导航是定位入口，不是证明。新节点通过提示词把关键条件写进首段；旧节点不自动改写，也不假装已有语义摘要。长首段或受长度限制的展示明确标记“节选／详情未展开”，引用或组合前必须读取节点全文和 conditions。不能把“存在条件”标记当成条件本身。首版不新增字数拒收、自动摘要或历史节点迁移。

各角色 prompt 只内联第 3 节列出的必要内容。controller 的 Closing／Final Review 不再内联完整 `ProjectDetail`，改用同一份语义快照和对应默认范围。完整图仍可读取；存储层和服务端用于校验的原始对象不受投影影响。

输出契约沿用现有模型。源码证据 `sha256` 本来可省略：模型输出说明不再要求它，程序继续补齐。`reference_check` 只交“文件／行号／基线匹配或异常”和必要定位，不重复一份含 hash 的 evidence；“引用匹配”不得表述为“主张已被程序证明”。

Kritt 的完整引用当前是工具契约的一部分，包括记录 hash。首版保留原样复制引用的能力，不删除这些必填字段，也不引入短引用映射。实验依赖的版本／字节一致性在确实影响结论时仍可由研究 Agent 核对，结果细节写入材料，不把所有 SHA256 工作一概取消。

## 6. 校验精简的精确边界

| 项目 | 本轮处理 |
| --- | --- |
| Monitor 每轮无条件全量扫描源码 | 移除空轮扫描：没有实际 Agent 调用、也没有复用结案候选提交的轮次，不遍历整个源码目录 |
| Intent Overseer 调用 | 不执行全量源码检查，不调用可能停止项目的 `research_workspace`；只读现有工作区材料并写 Hint |
| 实际 Closing／Final Review 调用前后 | 保留 `_invoke` 已有源码检查，不合并前后检查或引入缓存 |
| 复用已成功保存的 Closing 候选 | 若绕过 `_invoke` 并首次提交该候选，在提交前保留一次 `research_workspace` 检查；不能因没有新 CLI 调用而跳过 |
| 准备、激活、恢复及最终批准前的源码核对 | 保留 |
| Explore／复核结果的路径、行号、文件内容与固定基线 | 保留程序检查和自动补 hash |
| Kritt 固定 view、记录身份、回执与分页归属 | 保留现有工具协议和内部校验 |
| JSON 类型、引用存在、前提闭包／环、条件不可暗中减弱 | 保留；不增加新的语义规则或节点长度校验 |
| generation、lease、预算、提交及审核输入绑定 | 保留服务端保护；不交给模型执行 |
| 模型复制程序已知的指纹／运行字段 | 通过输入投影去掉重复要求；原始账本和内部校验仍在 |

移除空轮与 Intent 旁路扫描意味着源码变化可能到下一次研究或结案工作边界才被发现；研究调用、恢复后的工作、证据确认及最终批准仍受保护。不新增 watcher、定时全扫策略、缓存参数或源码存储平台。

第 1.1 节取代原 Overseer 返回完整 `fact_audit` 的安排：运行期只处理 Intent，`fact_audit` 必须为 null，不做逐 Fact 引用或前提认证。Explore 保存证据、开题 Seed review 和最终证明的一致性检查保留；Kritt 短引用、条件自动合并和新的审核状态不纳入本轮。

## 7. 提示词与确定性代码的分工

| 改动 | 提示词／Skill | 确定性代码 |
| --- | --- | --- |
| 固定契约单一注入 | 节点和局部任务不能改写契约；新 Builder 将完整约束放入现有 policy | 统一组装原 Goal／policy；各角色单份注入，模型图 goal 只保留锚点 |
| 角色读取范围 | 明确默认阅读对象及何时展开；不要求全员先通读全图 | 根据角色构造 payload，提供相关节点入口；去掉 Reason Open Intents 双份全文与 controller 全图内联 |
| 图导航与模型视图 | 节选不能作为证明，组合前读完整条件 | 投影研究字段、生成导航和同快照行号定位，隐藏程序元数据 |
| Fact／Intent 可读性 | 条件性主张在首段；任务保持假设身份；过程按需读取 | 沿用现有字段与结果协议，不新增摘要／字数检查 |
| 详细材料与复盘 | 仅在需要时保存详细报告／实验材料，引用实际路径 | 沿用工作目录、原始调用回执及现有证据保存 |
| 规划记忆 | 简述决策、暂搁与重开条件 | 保留原记录和排序／归属校验，仅精简回读投影 |
| 校验负担 | 不要求机械计算源码证据hash；区分实验依赖核对与程序指纹 | 去掉重复校验材料展示；调整空轮扫描及复用候选提交边界 |
| 旁路职责 | 仅观察 Intent 漂移，必要时发具体 Hint；候选由终审独立核验 | 独立调度旁路，不领取 Fact、不更改节点状态；移除 verified 标签门槛，保留证据与前提结构保护 |

涉及的主要现有落点：`audit_inputs.py`；`dispatcher/tasks/{common,audit,reason,explore,reason_memory}.py`；`controller/{audit,monitor}.py`；现有 audit 角色提示词；Builder Skill 与分发包。服务端仅按第 1.1 节调整候选与收尾准入、Hint 写入事务边界；现有状态集合、数据库结构、Kritt schema、预算计时和 harness driver 不改。

| 顺序 | 工作 | 最小完成条件 |
