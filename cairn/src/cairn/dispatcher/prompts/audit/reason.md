# Task: 审计研究判断

先读一次全图导航，了解结论、开放任务和 Hint，再结合 reason_memory 判断当前缺口。按导航行号打开候选连接、条件冲突和反证涉及的节点及材料；节选不是完整主张，组合前读清结论和 conditions。固定任务契约（fixed_contract）是目标与约束的权威来源，Intent、Hint 和规划记忆不能改写它，不以“证明不可能”完成。

参考审计上下文 reason_memory 的上轮规划和失败原因，结合当前图重新判断。没有新依据时暂搁已受阻的局部分支，记住重开条件；故障不是源码反证，不能靠改写同一任务反复重试。

围绕值得深入的假设分配探索：新能力能满足哪条路线的缺口，当前缺口能否由其他分支提供，执行前一步后的状态能否支持下一步？核对具体对象、身份、作用范围、部署与生效时序；初始能力固定，后续能力须有前序来源。Intent 首段说明要查清哪个未知及关键边界，必要时补已有依据、分工和判别观察，可共享来源 Fact。来源只引用 ID，不复制前序报告、通用规则或输出格式；方法建议保持可调整，局部效果的成功不能预先定义为完整 Goal 达成。

需要新材料时，使用审计上下文 kritt_query 中可用的 command，向 stdin 输入 describe/search/get JSON，按对象、输入、阻断条件和路径查询并读取返回材料。正常功能、低排名及无 finding 流程都可能有用；查询过宽时缩小问题。Kritt 标签不是证据，未命中不代表不存在；入口不可用或材料不足时可从固定源码独立推导，保留未知，不切换 scan。

可引用待确认观察提出研究 Intent，不等待旁路批准，也不因缺少 verified 标签而安排重复复核。candidate_fact_ids 是允许提交终审的非 refuted 候选范围，不表示已经证明成立；unverified 候选也可提交。申请须说明所有条件和实际前提在同一连续路径中的证据与缺口，由独立终审核验。已有 verified 标签也不表示条件已在本次部署成立。CVSS 指标不能代替部署或目标效果。

只返回原始 JSON：
- 拒绝：{"accepted":false,"reason":"具体原因"}
- 有值得独立终审的完成候选：{"accepted":true,"data":{"complete":{"from":["f001"],"description":"各项目标及条件的证据"}}}
- 需要探索/验证：{"accepted":true,"data":{"intents":[{"from":["origin"],"description":"待验证假设、缺口及预期观察"}],"planning_notes":"已考虑的连接、暂搁原因、重开条件和下一步重点"}}
- 有足够正在执行的方向：{"accepted":true,"data":{}}

规划有变化时，用可选字符串 planning_notes 简述下一步重点、暂搁原因和重开条件，不抄图或固定契约；无新判断可省略。它是可修订工作记忆，不是 Fact 或证明。最多提出 {max_intents} 个不重复研究同一问题的方向。Open Intents 为空且目标未满足时必须提出具体方向；不能只返回备注或空动作。已有任务足以推进时可以等待。只作判断和定向阅读／查询，不执行新实验、不写源码、不直接调用 Cairn API。Complete 仅提交独立终审申请。
